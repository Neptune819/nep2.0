## 二、推荐流水线（v3.0 4 级流水线）

推荐流程分为 4 个阶段：

```
[阶段 1] 数据加载 + 向量化
    anime_cache.json → tag 矩阵 → TF-IDF 向量
        ↓
[阶段 2] 召回 (KNN, 200-1200 候选)
    根据种子番剧 / 标签 / 历史 → KNN 粗排
        ↓
[阶段 3] 精排 = 15 因子加权几何平均 + 复合运算
    14 基础因子 + 历史因子(40%) → 加权几何平均
    + 心理模型乘性加成 (±5% 浮动)
    + 模式浮动 (explore ±15% / standard ±5% / conservative ±2%)
    + 调参后处理 (仅当用户调过，含因子交互)
        ↓
[阶段 4] 输出 top_k 番剧
```

## 三、15 因子评分系统

### 3.1 因子权重配置

| 因子 | 权重 | 类型 | 说明 |
|------|------|------|------|
| `tag` | 0.10 | 内容 | Jaccard 标签相似度 |
| `rating` | 0.08 | 质量 | AniList 均分 |
| `popularity` | 0.04 | 热度 | 人气排名 |
| `favourites` | 0.04 | 质量 | 收藏数 |
| `consensus` | 0.12 | 质量 | 综合质量指数 |
| `history` | **0.40** | 偏好 | 历史因素（v3.0 核心因子） |
| `era` | 0.03 | 偏好 | 年代匹配 |
| `format` | 0.03 | 偏好 | TV/Movie/OVA 格式 |
| `studio` | 0.03 | 厂牌 | 制作公司重叠 |
| `va` | 0.03 | 厂牌 | 声优重叠 |
| `staff` | 0.02 | 厂牌 | Staff（监督等）重叠 |
| `eps` | 0.02 | 细节 | 集数档位 |
| `duration` | 0.01 | 细节 | 单集时长档位 |
| `recency` | 0.03 | 先验 | 新番优先 |
| `quality_signal` | 0.02 | 先验 | 标签丰富度 |

### 3.2 评分公式

**加权几何平均**（阶段 4）：

```
base_score = exp( Σ(w_i × log(factor_i)) / Σ(w_i) )
```

几何平均比算术平均更严格——任何一个因子极低都会拉低总分。

**最终分组合**：

```
final_score = base_score × psych_mult × style_jitter × tuning_mult
```

| 乘数 | 说明 | 范围 |
|------|------|------|
| `base_score` | 15 因子加权几何平均 | 0~1 |
| `psych_mult` | 心理匹配乘性加成 | 0.1~3.0 |
| `style_jitter` | 模式随机浮动 | 0.85~1.15 |
| `tuning_mult` | 用户调参乘积 | 0.027~27.0 |

## 四、历史因子 v3.1 — 复合多信号匹配

历史因子是系统最核心的因子（权重 40%），采用 5 个信号的复合运算：

### 4.1 信号分解

| 信号 | 权重 | 算法 |
|------|------|------|
| **标签偏好** | 45% | 从全部历史构建加权 tag 频率表，候选命中率归一化，非线性压缩 (^0.7) |
| **厂牌匹配** | 20% | studio 重叠 +0.4，VA 重叠 +0.3 |
| **评分风格** | 15% | 高斯距离: `exp(-diff²/8)`，匹配用户偏好高分还是小众 |
| **格式偏好** | 10% | 历史格式众数 vs 候选格式 |
| **年代偏好** | 10% | 高斯距离: `exp(-diff²/50)`，约 7 年半衰期 |

### 4.2 复合公式

```
raw = tag_signal × 0.45 + brand_signal × 0.20 + score_signal × 0.15
    + fmt_signal × 0.10 + year_signal × 0.10

val = sigmoid(6.0 × (raw - 0.35))  →  映射到 [0.1, 1.0]
```

使用 sigmoid 而非线性映射的优势：
- 中间区域（raw ≈ 0.35）敏感度高，微小差异能影响排名
- 极端区域（raw 接近 0 或 1）敏感度低，避免过度放大

### 4.3 标签偏好信号详解

```python
# 1. 构建加权 tag 频率表
for hist_anime, hist_rating in history:
    weight = (hist_rating / 10) ^ 1.5  # 非线性：高评分指数级更重要
    for tag in hist_anime.tags:
        tag_weights[tag] += weight

# 2. 候选命中
hit_weight = sum(tag_weights[tag] for tag in candidate.tags)
tag_signal = min(1.0, hit_weight / (total_weight × 0.3))
tag_signal = tag_signal ^ 0.7  # 压缩：避免 tag 多的番剧过度占优
```

## 五、调参系统 v3.2 — 三档按钮 + 复合运算

### 5.1 三档倍率

| 档位 | 低档 (低) | 中档 (中) | 高档 (高) |
|------|-----------|-----------|-----------|
| 低影响因子 | ×0.7 | ×1.0 | ×1.3 |
| 中影响因子 | ×0.8 | ×1.0 | ×1.2 |
| 高影响因子 | ×0.3~0.5 | ×1.0 | ×2.0~3.0 |

### 5.2 因子交互（复合运算）

调参不是简单的独立乘法，相关因子之间存在交互加成：

```python
# 基础倍率
base_mult = TUNING_TIERS[tier][factor][gain]

# 交互加成
bonus = 1.0

# 1. 标签×厂牌协同
if factor == "tag" and gain > 0 and studio_gain > 0:
    bonus *= 1.0 + 0.3 * min(gain, studio_gain)

# 2. 历史×标签共振
if factor == "history" and gain > 0 and tag_gain > 0:
    bonus *= 1.2

# 3. 质量共振
if factor in ("rating", "consensus") and gain > 0 and other_gain > 0:
    bonus *= 1.15

# 4. 厂牌联动
if factor in ("studio", "va", "staff") and gain > 0:
    brand_count = count(studio, va, staff 中 gain > 0 的)
    if brand_count >= 2:
        bonus *= 1.0 + 0.2 * (brand_count - 1)

# 5. 历史因子值高时放大
if factor == "history" and breakdown["history"] > 0.7:
    bonus *= 1.0 + 0.5 * (breakdown["history"] - 0.7)

return base_mult * bonus
```

## 六、心理画像系统

### 6.1 维度结构

心理画像包含 24 个维度，按依赖顺序推断：

```
人格层 → 需求层 → 情感层 → 叙事层 → 价值层

├── 大五人格 (OCEAN)
│   ├── 开放性 (Openness)
│   ├── 尽责性 (Conscientiousness)
│   ├── 外向性 (Extraversion)
│   ├── 宜人性 (Agreeableness)
│   └── 神经质 (Neuroticism)
├── MBTI 倾向
├── 九型人格
├── 原型偏好 (Hero/Sage/Explorer/Outlaw/...)
├── 防御机制 (Fantasy/Sublimation/Humor/...)
├── 马斯洛需求层次
├── SDT 需求 (Autonomy/Competence/Relatedness)
├── 依恋类型 (Secure/Anxious/Avoidant)
├── 叙事偏好 (Linear/Multi-thread/Stream-of-consciousness)
└── 世界观认同 (Realistic/Fantasy/Sci-fi/Dystopian)
```

### 6.2 标签→心理维度映射

系统维护一张 **150 个标签到心理维度的映射表**，示例：

| 标签 | 映射维度 |
|------|----------|
| `Action` | archetype: hero, defense: sublimation |
| `Psychological` | big_five: {N: 0.3, O: 0.4}, defense: intellectualization |
| `Isekai` | archetype: explorer, defense: fantasy |
| `Slice of Life` | big_five: {A: 0.3}, sdt: relatedness |
| `Dark Fantasy` | archetype: outlaw, worldview: dystopian |

### 6.3 心理匹配因子

心理匹配作为独立乘性加成（不参与几何平均）：

```
psych_mult = 1.0 + (psych_score - 0.5) × 2.0
psych_mult *= (1 + random(-0.05, 0.05))  # ±5% 浮动
psych_mult = clamp(0.1, 3.0)
```

心理匹配内部权重：

| 维度 | 权重 |
|------|------|
| 原型匹配 | 25% |
| 需求匹配 | 25% |
| 防御机制匹配 | 20% |
| 叙事匹配 | 15% |
| 世界观匹配 | 15% |

## 七、发现型推荐引擎

### 7.1 三种发现类型

| 类型 | 算法 | 筛选条件 |
|------|------|----------|
| **被低估佳作** | 五层复合权重算法 | score≥5.5, favs≥30, rank≤50000 |
| **经典老番** | 年代加权 | year≤阈值, score≥6.5, favs≥50 |
| **口味盲区** | 标签盲区映射 | score≥6.0, favs≥50 |

### 7.2 五层复合权重算法（被低估佳作）

```
[层 1] 基础分布函数
    exp_decay, gaussian, log_growth, sigmoid, power_law
        ↓
[层 2] 调制函数
    正弦波调制 → 波浪形分布
        ↓
[层 3] 按风格混合
    探索型: log_growth + sigmoid 主导
    标准型: 双峰 gaussian + log_growth
    保守型: exp_decay + gaussian 主导
        ↓
[层 4] 软门槛
    sigmoid 软激活 / inv_sigmoid 软上限
        ↓
[层 5] 多重随机扰动
    整体偏移 ±20% + 局部噪声 ±10% + 3% 异常值
```

### 7.3 探索型特殊处理

探索型推荐对低分番剧有"发现加分"：

```python
if style == "explore" and score < 7.5:
    discovery_bonus = 1.0 + max(0, 7.5 - score) * 0.4
    quality_score *= discovery_bonus
# 6.0 分 → ×1.6, 6.5 分 → ×1.3, 7.0 分 → ×1.1
```

## 十、数据源与处理

### 10.1 数据采集

- **AniList GraphQL API**：主数据源，包含番剧元数据、标签、声优、Staff
- **Bangumi API**：补充中文名、简介翻译

### 10.2 数据处理流程

```
AniList API → 14,754 部原始数据
    → 过滤国漫 (~1,344 部)
    → 过滤 R18 (~82 个标签)
    → 名称翻译 (name_cn)
    → 简介翻译
    → 声优中文名映射
    → 标签中文翻译
    → 续集系列识别 (543 个系列)
    → 最终: 13,542 部
```

### 10.3 向量化

使用 scikit-learn 的 TF-IDF + NearestNeighbors 做标签向量化：

```python
# 标签 → TF-IDF 向量
vectorizer = TfidfVectorizer()
tag_matrix = vectorizer.fit_transform(all_tags)

# KNN 召回
nn = NearestNeighbors(n_neighbors=1200, metric='cosine')
nn.fit(tag_matrix)
candidates = nn.kneighbors(query_vector)
```

## 十一、续集检测算法

续集检测通过标题前缀匹配识别同系列作品：

```python
SERIES_PATTERNS = [
    r'(.+?)\s+Season\s+\d+',     # "Attack on Titan Season 2"
    r'(.+?)\s+S\d+',              # "AOT S2"
    r'(.+?)\s+Part\s+\d+',        # "AOT Part 2"
    r'(.+?)\s+Cour\s+\d+',        # "AOT Cour 2"
    r'(.+?)\s+第\d+[期季]',        # "进击的巨人 第2期"
    r'(.+?)\s+[IVX]+$',           # "Final Fantasy VII" → "Final Fantasy"
    r'(.+?)\s+\(\d{4}\)',         # "Title (2024)"
    r'(.+?)\s+(OVA|Movie|Special)',
]
```

已识别 543 个系列，推荐时自动过滤同系列作品。

## 十二、性能与限制

### 12.1 性能指标

| 操作 | 耗时 |
|------|------|
| 冷启动加载 | ~3 秒（加载 44MB JSON） |
| 搜索响应 | <100ms |
| 推荐计算（200 候选） | ~200ms |

### 12.2 已知限制

1. 数据存储依赖 JSON 文件和 localStorage，无持久化数据库
2. 续集检测基于标题正则，无法覆盖所有情况
3. 心理画像映射为静态表，无法学习用户反馈
4. 单机部署，无并发处理能力
5. 声优中文别名仅 50 条常用
